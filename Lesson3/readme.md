# Deploying web api with `App Service`

В целом у вас есть разные варианты размещения вашего приложения на Azure, мы с вами начнем с самого простого и высокоуровневого метода чтобы у вас на курсовой все было легко и просто.

`App Service` - это уже настроенная виртуальная машина на Linux или Windows для вашего web приложения. Там вы уже выбираете нужнуб для вас среду .NET и загружаете свой проект. В целом есть два метода загрузки.

1. Github (Github Actions)
2. Azure Docker Container Service

В первом варианте вы просто загружаете свое приложение на `Github` и `App Service` берет последний коммит на главную ветку и делает его `deploy`. У такого метода по моему мнению нет минусов. Из самых главных плюсов могу отметить непрерывную разработку и развертку вашего приложения, что значит что каждый ваш push в Github будет обновлять версию вашего приложения.

Второй вариант предпологает использования `Docker` и очень хорош для больших приложений с использованием различных сред, как .NET, MS SQL, Redis, Node JS, React и т.д. То есть если в вашем проекте есть несколько слоев(то есть проект состоит из других проектов) и вам надо обновлять сразу весь `Docker Container`, то этот вариант явно для вас. Но в первом варианте это все тоже возможно, просто тогда N-layered будет работать в App Service, а все остальное должно хоститься отдельно.

# Вариант с IIS

`IIS` - Internet Information Services

Это часть операционной системы Windows, которая позволяет вам создавать свои сайты. `Azure` дает вам возможность создать свою виртульную машину и настроить его как вам угодно. На ней вы можете настроить IIS и сделать `publish` своего проекта. В таком случае вы пользуетесь либо `GUI` своего `IDE` и делаете publish, либо используете комманду dotnet publish. Такой подход соберет ваше решение в одну папку и все будет состоять только из готовых .dll Эту папку вам надо будет перенести на сервер либо в ручную, либо через уже настроенный `FTP`. В целом это очень тривиальный подход. На наши дни он абсолютно неактуален, единственная причина по которой мы будем это рассматривать это то, что некоторые компании в Баку до сих пор так работают.

- В чем же проблема ?

Вам вручную надо настраивать сервер, вплоть до его безопастности и сетевой конфигурации. Если вы не настроете deploy через FTP, то вам придется вручную переносить туда эту папку что останвливает ваше приложение. Сам FTP тоже не безопастный, и вам придется его конфигурировать под sFTP, дальше вас конечно же ждут проблемы с SSL.
